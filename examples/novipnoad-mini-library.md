# NO视频自定义媒体库

脚本：`novipnoad-mini-library.js`，版本 **1.2.8**。

支持首页懒加载、分类、搜索、详情、选集和 TMDB 资源匹配。站点地址可在媒体库参数中切换；单集帖按标题中的季、集编号展示，合集保留原站的单个资源。

## 播放流程

1. 每次播放先在 App 的 WebKit 中后台打开真实详情页；页面完成站点跳转后，从返回的最新详情 HTML 读取选集和播放器参数。详情页 URL 不随选集改变，脚本会用所选集按钮的 `data-vid`（对应 `episodeId`/`versionId`）覆盖播放器参数中的集数 ID，因此初始 iframe 仍显示 E01 也不会把 E01 当成当前选择。
2. 读取最新播放器 HTML，获取当前站点的解密组件，在 WebKit 的最小文档中执行原站授权函数。
3. 收到 AUTH 后立即请求播放接口，并使用当前站点的 WebAssembly 组件解密。
4. 将最终媒体地址、容器和请求头交给 App 原生播放器。

不需要额外播放服务。WebKit 只负责后台打开真实详情页、站点授权和解密；不加载网页播放器，也不等待 READY 或网页视频播放。若站点要求浏览器验证，由 App 的浏览器宿主处理。授权参数和播放地址不写入持久缓存。浏览详情时最多缓存最近一条页面 60 秒；每次播放解析都会绕过这份缓存，重新打开详情页并用当前 pkey 和所选集 ID 生成播放参数。若新参数在请求过程中仍过期，脚本会再打开一次详情页并重试同一集。

旧的固定 RC4 解密已移除。最小文档内部的授权和接口请求限时 10 秒，浏览器请求设置 14 秒超时（实际下限由 App 宿主控制）；失败会返回明确错误，便于重新尝试。播放时刷新详情允许 App 浏览器会话回退以取得有效参数；播放器与解密接口请求仍关闭浏览器自动回退。

## 验证与更新

源站的页面可能出现 Cloudflare 或其他站点跳转，播放前的真实详情页会在 App 中打开，完成页面操作后继续解析。后台 TMDB 匹配不会自动弹出验证；已匹配到的资源不会因后续别名查询被验证拦截而丢失。

在 App 中更新或重新导入此脚本后，返回详情重新选择资源并播放。当前修改只涉及脚本及文档，无需为本次播放流程修复重新编译 App；App 需具备内联 `Widget.browser.fetch({ html, baseURL })` 能力。

本地回归：

```sh
node --check docs/examples/novipnoad-mini-library.js
node scripts/test_novipnoad_mini_library.js
node scripts/validate_mini_library_examples.js
```

2026-10-20 使用工程实际生成的文档在真实 WebKit 中验证：播放接口返回 `code: 200`，约 1 秒取得媒体信息；工程解析结果为 MP4，最终地址的 Range 请求返回 `206 / video/mp4`，内容包含有效 MP4 `ftyp`。这些检查覆盖接口解析和资源可访问性；App 真机完整播放仍需实际确认。
