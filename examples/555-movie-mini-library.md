# 555电影自定义媒体库

脚本：`docs/examples/555-movie-mini-library.js`，默认站点为 <https://www.1737k.com/>。

在自定义媒体库中导入 JS 文件即可使用；已经加入工程的媒体库广场目录。站点换域名时，可在媒体库参数中修改“站点地址”，填写 HTTP/HTTPS 首页地址。内容抓取、站点校验与播放地址解码由 JS 完成，最终 HLS/视频地址交给 App 原生播放，不需要独立播放服务。

## 1.1.3 域名迁移与配置

默认站点更新为 `https://www.1737k.com`，媒体库配置中的“站点地址”支持随时修改，首尾空白和末尾 `/` 会自动去除，留空恢复默认。未设置过地址的媒体库会采用新默认；手动保存过旧地址的媒体库需在配置中改成新地址或清空该项。自定义地址优先于默认地址，首页、频道、分类、搜索、详情、匹配接口和播放页的请求及 Referer 均跟随配置；媒体 CDN 地址及签名参数保持原样，缓存和站点会话按域名隔离。更新或重新导入脚本即可使用，App 沿用现有参数配置功能。

新站同时更换了页面路径和资源 ID 编码，本版兼容首页卡片 `/play/<ID>.html`、线路 `/see/<ID>-<sid>-<nid>.html`、频道 `/vodtype/<ID>.html` 和分类 `/vodshow/...html`，并保留旧格式 action 的读取。匹配候选使用新站已核对的 ID 编码，不再将旧编码拼进详情地址；片名、年份、类型与季集校验沿用原有规则。

## 支持的功能

- 首页横幅轮播，以及站点推荐的电影、剧集、动漫、综艺等栏目；只读取当前推荐 tab，避免混入隐藏分类。
- 电影、剧集、动漫、综艺、短剧频道推荐；“全部”入口进入站点完整片库。频道推荐本身没有分页，不会伪造下一页。
- 正式搜索页、完整分类页按实际下一页链接翻页，支持页面参数顺序不同的 MacCMS 路径。
- 详情海报、年份、简介、演员、相关推荐，以及剧集选集和电影多版本。
- 按真实播放链接对应线路，按集名对齐剧集；某线路缺集时不将下一集误配给当前集。预告、分段与命名特别篇保持独立。
- 支持 MacCMS 播放地址的三种公开编码，直接返回 HLS 或视频地址。只提供第三方网页解析的线路会提示切换线路。
- 可参与 App 聚合搜索、播放历史和 TMDB 详情页资源匹配。

## TMDB 资源匹配

1.1.0 起，`matchResources` 使用 `/index.php/ajax/suggest?mid=1&wd=片名&limit=20` 查询候选，不调用带验证码的 HTML 搜索页。接口返回数字资源 ID，脚本按已验证的公开 MacCMS URL 编码转换为本站详情 ID，再读取详情补全影片、真实季集和线路；返回内嵌详情与目标集线路，供 App 原生资源选择器使用。

接口没有 TMDB/IMDb、年份和媒体类型筛选，因此脚本按片名、原名、别名、年份、类型与季集核对，不将传入的 TMDB ID 当作站点已确认的 ID。最多查询三个不同名称、读取六个候选详情，首个名称找到有效资源后停止。剧集按源标题识别季号，并按真实集号选择目标集；不按线路的 `nid` 猜集数，未标明季号的条目不会匹配到第二季及以后。不同季优先核对当季年份，不把首播年份强套到后续季。

匹配过程中遇到网络错误或验证页不会弹出浏览器，也不会回退到网页搜索。没有可靠候选时返回空结果。这个接口是有限的搜索建议接口，不支持完整结果分页；媒体库内的普通搜索仍保留正式搜索页与分页。

1.1.2 修复 TMDB 详情页资源匹配为空：App 的 `Widget.http.get()` 会自动将 JSON 响应解析成对象，旧脚本将它转成了 `[object Object]`，导致建议接口解析失败、无法读取候选详情。现在兼容已解析的 JSON 对象与原始响应字符串，HTML 解析保持原样。已安装的媒体库需更新或重新导入脚本。

## 站点验证

部分请求会出现站点的短时计算校验，脚本只解析明确字段并调用宿主 MD5；不执行远端 JS，计算时间和次数均有限制。

完整片库和搜索可能要求人工验证码。需要包含本次 `verificationSelector` 宿主改动的新版 App：HTTP 命中验证码后才进入浏览器，显示原站表单供用户输入；表单消失后自动返回原生列表，并复用该站会话。取消、超时或旧版 App 不支持时会明确报错，不会误报为“没有结果”。tvOS 当前不支持这个浏览器验证流程，因此遇到验证码时分类/搜索受限；普通首页、详情及可直连播放仍可使用。

1.1.1 修复点击验证码输入框就报脚本失败：站点会在输入框获得焦点时移除 `mac_verify` 样式类，因此验证标记改为 `.mx-mac_msg_jump input[name="verify"]`，持续等待验证输入框消失。点击、输入以及验证码错误后仍保留验证页面。

2026-10-20 已使用 burge 工程中的 REA 6.4.0 分析公开前端脚本，并通过独立临时 Chrome 抓取实际页面和网络请求：搜索与完整分类页均返回了含 `mac_verify` 表单的“系统安全验证”。进一步核查确认，建议接口的数字 ID 虽不能直接打开详情，但按公开 URL 编码转换后可用，20 组真实 ID/详情路径全部一致，电影和第四季剧集均已走通候选、详情、播放页与 HLS 请求。`/api.php/provide/vod/` 返回 `closed`；`/index.php/ajax/data` 忽略片名与外部 ID 筛选且不含播放字段，因此没有用它们冒充资源匹配接口。目前详情和播放页仍需解析 HTML。

缓存以站点地址隔离：首页 60 秒、匹配候选与详情线路元数据 90 秒、下一页链接 300 秒、站点会话最多 480 秒。最终媒体地址每次播放重新获取。站点 Cookie 只用于本站请求，不附到图片和媒体 CDN。

## 本次宿主改进

- `Widget.browser.fetch(url, { verificationSelector: '.mx-mac_msg_jump input[name="verify"]' })`：只有实际出现指定表单才显示并等待用户验证，完成后返回 HTML 和 Cookie；保留 Cloudflare、取消、超时流程。
- 浏览器任务串行执行，避免叠加验证界面；用户取消会清理同站排队任务，页面请求自身取消只停止对应任务。超时独立于页面脚本，主线程延迟后也不会重新弹出已超时的验证。
- 页面加载、跳转和快照按当前导航核对，空快照或 JS 执行错误不会误判为验证成功；正常刷新及跳转不中断验证。验证界面适配安全区域，取消按钮保持可操作。
- Cookie 保留域、路径、HTTPS 和有效期限制，验证后新的有效会话覆盖同名旧值，并同步到浏览器供刷新和表单提交使用。旧版无作用域缓存会失效，升级后可能需要重新验证一次。
- 详情页启动播放时优先使用资源版本 action 的 itemId，保证不同线路覆盖内容 ID 的行为与卡片入口一致。
